A small ScyllaDB service on Azure

One operator creates a 3-node ScyllaDB cluster from a web page, writes a row, backs it up to Azure Blob, restores it, and recovers from a single dead VM. Scylla Manager and Grafana run as Docker on a fourth VM.

Source of truth: docs/README.md. This page is the picture; the markdown is the contract.

Layout

Control plane

  • Python API, UI, and worker
  • SQLite for intent, progress, audit
  • Runs on the operator laptop for the demo

Ops VM · 10.0.1.4

  • Scylla container for Manager's own data
  • Scylla Manager
  • Prometheus, Grafana, Alertmanager, Loki

Data nodes

  • 10.0.1.10 · .11 · .12
  • Ubuntu 24.04, Scylla, Manager agent
  • RF=3, one datacenter

Backup resource group

Blob container scylla-backup. Data-node managed identities upload snapshots. This group survives cluster delete for 7 days.

Not on the internet

Gossip, metrics, and the Manager agent listen on the private subnet. CQL and Grafana allow the operator IP only.

Build versus reuse

Create path

  1. API accepts a name and returns an operation id.
  2. Worker creates network, backup storage, identity, and NICs with fixed private IPs.
  3. Ops VM comes up. Node 0 comes up and answers CQL. Nodes 1 and 2 join.
  4. Worker stores host ids, creates CQL roles, points agents at the storage account, registers Manager, starts Grafana.
  5. Daily backup and weekly repair schedules exist. Status becomes ready.

When a node dies

What we seeWhat we do
VM stopped, or Scylla not answering, peers healthyStart the VM or restart the service
VM gone, the other two are upNew VM on the same NIC and IP, Scylla replace-boot, then a Manager repair
Two data nodes unhealthyDo nothing automatic. Mark the cluster degraded and audit it as critical

Replacing a node without quorum can throw away the only remaining copy of a write. The freeze is the safety rule.

Known gaps

  • The control plane, templates, and tests are in the repo. No live Azure cluster has been created.
  • Scylla package URL, Manager image tag, and the replace boot flag are confirmed in T11, not guessed here.
  • Dollar cost is computed on the day the SKU is pinned.
  • The 256 GiB data disk may force Scylla developer mode. The cluster record will say so.
  • Health automation is slower than Grafana, because it uses Azure Run Command.
  • No TLS, no multi-zone RF, no Entra ID, no second cluster. Named on purpose in the limitations doc.
